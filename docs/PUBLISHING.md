# MusicSCAN 0.7.1 BETA publishing guide

This folder is the source repository prepared for upload. The installable ZIP
is a separate build artifact. No live GitHub repository, CurseForge project ID
or public listing URL is assigned by these files.

## Release files

Before uploading this beta, complete the short in-game checks in
docs/CLIENT-TEST.md. Local tests verify the logic; the delay still needs a real
Delve / hearth test against the audio engine.

| Item | Purpose |
| --- | --- |
| `dist/MusicSCAN-0.7.1-BETA.zip` | Installable addon; attach to GitHub Releases and upload to CurseForge |
| `dist/SHA256SUMS.txt` | Optional integrity check for the installable ZIP |
| `README.md` | GitHub project overview and complete player guide |
| `docs/DESCRIPTION.md` | Public description copy for CurseForge and the website |
| `docs/RELEASE-NOTES.md` | Copy for this beta release's changelog field |
| `docs/MusicSCAN-0.7.1-BETA-Publishing.docx` | Editable feature, installation, command and patch-note copy |
| `assets/MusicSCAN-badge.png` | Square master artwork for the project and website |

## GitHub

1. Create a new independent repository named **MusicSCAN** in the intended
   personal account or organization. Use a public repository for public source
   browsing. Keep it separate from VaultSCAN.
2. Upload the contents of this source folder at the repository root, preserving
   MusicSCAN/, assets/, catalog/, docs/, tests/ and tools/. Include the supplied
   .gitignore and .gitattributes. Do not upload dist/ as source.
3. Use the existing README and LICENSE.txt rather than generating replacements.
   The beta uses All Rights Reserved with permission for personal installation
   and local modification. Confirm this license choice before publishing.
4. Commit with a message such as **Prepare MusicSCAN 0.7.1 BETA**.
5. Create a release with tag **v0.7.1-beta** and title **MusicSCAN 0.7.1 BETA**.
   Mark it as a **pre-release**. Paste docs/RELEASE-NOTES.md as its description.
6. Attach the installable ZIP and SHA256SUMS.txt generated by
   `python3 tools/build_release.py`. The automatic source ZIP is not the addon
   download; the README directs players to the installable asset.
7. Use the actual repository and Issues URLs in the CurseForge Source and
   issue-tracker fields after the repository exists.

## CurseForge

Create a new World of Warcraft project through the official author dashboard:
https://authors.curseforge.com/#/projects/create/choose-game

| Field | Prepared value |
| --- | --- |
| Project name | MusicSCAN |
| Summary | Play Blizzard's built-in zone music anywhere, with searchable expansion browsing and saved favorites. |
| Game and project type | World of Warcraft addon |
| Category | Audio & Video, if available in the current submission form |
| Logo | assets/MusicSCAN-badge.png, square PNG |
| Description | docs/DESCRIPTION.md or the matching Word document copy |
| Website | https://kilobytes.dev/musicscan/ |
| License | All Rights Reserved, matching LICENSE.txt; confirm before publishing |
| Dependencies | None |
| File | MusicSCAN-0.7.1-BETA.zip |
| Display name | MusicSCAN 0.7.1 BETA |
| Release type | Beta |
| Changelog | docs/RELEASE-NOTES.md |

Keep the project name simply **MusicSCAN**; the file display name carries the
version. Choose the Retail game version actually used for the in-game tests.
The working TOC interface remains **120105**. Verify the current client with
`/dump GetBuildInfo()` if needed; do not tag untested game versions or Classic.
No CurseForge project ID or dependency metadata has been invented in the TOC.

The ZIP has the required single MusicSCAN root with MusicSCAN.toc directly
inside. The supplied logo is square and exceeds the published 400 by 400 PNG
minimum. Uploading a file submits the project for moderation; approval is a
separate step. Preview formatting and links before submitting.

Keep the file's release type **Beta** as requested. Beta delivery and visibility
can differ from normal Release files in the CurseForge app. The current support
articles differ on whether a first Beta alone makes a new project discoverable;
confirm that behavior in the author dashboard rather than relabeling the file.
